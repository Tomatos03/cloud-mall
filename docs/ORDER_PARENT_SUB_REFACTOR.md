# 订单系统父子订单重构说明文档

## 📋 重构概述

### 重构目标
解决购物车多店铺结算时的订单管理问题，引入**父子订单**概念，使订单结构更加清晰、查询更加简单。

### 重构前问题
1. ❌ 多店铺订单关联不对称（第一个订单 `parent_id = NULL`，其他订单有值）
2. ❌ 第一个订单地位特殊，逻辑混乱
3. ❌ 查询"一次下单的所有订单"复杂
4. ❌ 无法管理整体订单状态

### 重构后优势
1. ✅ 所有子订单地位平等
2. ✅ 父订单统一管理整体信息（总价、状态等）
3. ✅ 查询简单直观：`SELECT * FROM orders WHERE parent_id = ?`
4. ✅ 便于扩展（整体退款、整体评价等）

## 📊 数据库变更

### 1. 执行 SQL 脚本

```bash
# 执行数据库迁移脚本
mysql -u root -p online_mall < docs/db_migration_order_parent.sql
```

### 2. 新增字段

| 字段 | 类型 | 说明 | 默认值 |
|------|------|------|--------|
| `order_type` | VARCHAR(20) | 订单类型：PARENT/SUB/NORMAL | NORMAL |

### 3. 字段修改

| 字段 | 修改内容 |
|------|----------|
| `parent_id` | 更新注释：父订单ID（多店铺场景） |
| `store_id` | 允许 NULL（父订单没有店铺） |
| `num` | 更新注释：父订单表示子订单数量，子订单表示商品项数量 |

### 4. 新增索引

- `idx_parent_id`：父订单ID索引
- `idx_order_type`：订单类型索引
- `idx_user_order_type`：用户订单类型联合索引

## 🔄 订单类型说明

### OrderType 枚举

| 类型 | Code | 说明 | 使用场景 |
|------|------|------|----------|
| **PARENT** | PARENT | 父订单 | 多店铺购物车结算（聚合订单） |
| **SUB** | SUB | 子订单 | 多店铺场景下的单个店铺订单 |
| **NORMAL** | NORMAL | 普通订单 | 单店铺场景（立即购买或单店铺购物车） |

### 场景2：多店铺下单

**用户操作**：购物车勾选 3 个店铺的 5
 个商品结算

```
orders 表（4条记录 = 1个父订单 + 3个子订单）：
┌────┬───────────┬──────────┬──────────┬─────────────┬─────┬────────────┐
│ id │ parent_id │ no       │ store_id │ total_price │ num │ order_type │
├────┼───────────┼──────────┼──────────┼─────────────┼─────┼────────────┤
│ 1  │ NULL      │ P2025... │ NULL     │ 2369200     │ 3   │ PARENT     │ ← 父订单
│ 2  │ 1         │ 2025...  │ 10       │ 1179700     │ 2   │ SUB        │ ← 子订单
│ 3  │ 1         │ 2025...  │ 20       │ 699900      │ 1   │ SUB        │ ← 子订单
│ 4  │ 1         │ 2025...  │ 30       │ 489600      │ 2   │ SUB        │ ← 子订单
└────┴───────────┴──────────┴──────────┴─────────────┴─────┴────────────┘

order_item 表（5条记录）：
┌────┬──────────┬──────────┬─────────────┐
│ id │ order_id │ goods_id │ total_price │
├────┼──────────┼──────────┼─────────────┤
│ 1  │ 2        │ 101      │ 799900      │ ← 关联子订单2
│ 2  │ 2        │ 102      │ 379800      │
│ 3  │ 3        │ 201      │ 699900      │ ← 关联子订单3
│ 4  │ 4        │ 301      │ 399900      │ ← 关联子订单4
│ 5  │ 4        │ 302      │ 89700       │
└────┴──────────┴──────────┴─────────────┘
```

**父订单字段说明**：
- `no`：父订单号（前缀 "P"）
- `store_id`：NULL（父订单不属于任何店铺）
- `total_price`：所有子订单的总价（2369200 = 1179700 + 699900 + 489600）
- `num`：子订单数量（3）
- `order_type`：PARENT
