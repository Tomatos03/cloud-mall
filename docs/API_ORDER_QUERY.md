## 1. 概述

订单分页查询接口分为两种，针对不同的使用场景：

| 接口类型 | 使用场景 | 返回数据 | 查询范围 |
|---------|---------|---------|---------|
| **管理端接口** | 后台订单管理 | 订单列表（Order） | 普通订单 + 子订单 |
| **用户端接口** | 前台我的订单 | 订单聚合视图（OrderAggregateVO） | 父订单 + 普通订单 |

---

## 2. 接口分类

### 2.1 为什么要分两个接口？

#### **管理端需求：**
- 商家需要看到**每个店铺的订单**（子订单），方便单独发货、处理售后
- 管理员需要查看**所有订单明细**，包括父订单和子订单
- 需要按店铺、订单类型、子订单等多维度筛选

#### **用户端需求：**
- 用户只想看到**自己下的订单**（一次购买 = 一个订单）
- 多店铺购买时，显示为**一个聚合订单**，展开后看到各店铺的商品
- 不需要看到"子订单"的概念，符合用户心智模型

## 3. 管理端接口

### 3.1 基本信息

| 项目 | 说明 |
|------|------|
| **接口路径** | `GET /manager/order/page` |
| **请求方式** | GET |
| **权限要求** | 管理员或商家 |
| **返回类型** | `I
Page<Order>` |

### 3.2 权限控制

| 角色 | 查询范围 |
|------|---------|
| **管理员（ADMIN）** | 可以查询所有订单（普通订单 + 子订单） |
| **商家（MERCHANT）** | 只能查询自己店铺的订单（普通订单 + 子订单） |
| **普通用户（NORMAL）** | ❌ 无权访问 |
